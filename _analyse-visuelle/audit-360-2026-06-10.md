# Rapport d'audit 360° — metal-pliage.fr
_Cabinet d'audit IA — 10 départements, double passage, 151 findings confirmés — 10/06/2026_

## 1. Verdict général — **5,2 / 10**

Le site est une belle vitrine qui **ne vend rien**. Le design est soigné mais incohérent sous le capot (4 oranges, 16 line-heights, zéro système de tokens), et surtout : **le paiement Stripe est cassé en production** (clé `pk_test` + endpoint `/api/create-checkout-session` qui n'existe pas sur GitHub Pages), le tracker Brevo est un placeholder `VOTRE-CLE-BREVO` répliqué sur 36 fichiers, et la page Réalisations affiche « Photos de chantiers à venir » à la place de tout portfolio. Tu paies de la publicité (ou du SEO) pour amener des gens sur une boutique dont la caisse est débranchée et dont la preuve de crédibilité (photos, avis, fiches techniques) est vide. La note pondérée est tirée vers le bas par la couche conversion/business (le cœur du métier e-commerce), pas par le code, qui est globalement honnête.

Pondération : Marketing/Conversion et Mobile pèsent le plus (c'est là que se joue le CA, 70% mobile), le polish CSS le moins.

## 3. Les 5 vérités convergentes (priorité absolue)

Ces problèmes sont signalés **indépendamment par plusieurs départements** — c'est le signal le plus fiable du dossier.

1. **Le checkout est mort + Stripe en mode test** — signalé par Marketing (×3 findings), Benchmark (×2), Persona Antoine (×2). `cart.js:10` = `pk_test`, `cart.js:210` appelle `/api/create-checkout-session` qui renvoie 404 sur GitHub Pages (site statique, `server.js` jamais déployé). **Aucune vente en ligne n'est possible aujourd'hui.** C'est LE blocage n°1.

2. **Brevo = `VOTRE-CLE-BREVO` sur 36 fichiers** — signalé par SEO, Marketing (×3), Perf/Code, Élodie, Antoine, Karim. Le tracker charge `sibautomation.com/sa.js?key=VOTRE-CLE-BREVO` qui échoue partout. Zéro relance J+1/J+5/J+10, zéro capture de lead. Soit on met la vraie clé, soit on supprime les 8 lignes mortes ×36.

3. **Cibles tactiles sous le seuil + typos minuscules** — signalé par Accessibilité, Mobile, Benchmark, Karim (massivement). Hamburger 28px, swatch RAL 18px et 22px (pliage), qty-btn 32px, bouton d'aide 18px, `.btn-configurer` ~24px, typos 0.58-0.72rem (9-11px). Sur 70% de trafic mobile + chantiers gantés/soleil = friction maximale.

4. **Portfolio + preuve sociale = le vide** — signalé par SEO, Marketing, Benchmark, Élodie. `realisations.html:244-299` = 6 placeholders « Photos de chantiers à venir », **zéro `<img>`**. 3 avis seulement. Pour des architectes prescripteurs et des particuliers timides, l'absence de preuve tue la conversion plus que n'importe quel bug CSS.

5. **44 brouillons + 135 MB d'assets pollués en production** — signalé par Perf/Code (×4 findings). 44 fichiers `variants/iter/preview/cursor/effets-*` trackés en git, 130 MB d'images inutilisées, dossier `_orig/` de 39 MB, robots.txt fragile à 24 règles. Repo et déploiement gonflés sans raison.

## 5. Quick wins < 2h (à faire en premier, dès cette semaine)

1. **Brevo (0,5h)** — vraie clé OU suppression ×36. Code mort qui charge un 404 sur chaque page.
2. **`inputmode="numeric"` (1h)** — déjà présent dans Training-Visuel, c'est un rollback. Gain mobile immédiat.
3. **Skip-link (0,5h)** — accessibilité, conformité, copier-coller le snippet existant.
4. **Panier `aria-hidden` (1h)** — le panier ouvert est invisible aux lecteurs d'écran.
5. **Captcha=true + canonical 404 + meta keywords (0,5h)** — `contact.html:412`, `404.html:11`, `index.html:8`.
6. **Hamburger 44px (0,5h)** — une règle CSS, débloque le menu mobile.
7. **og:image PNG dans le schema (0,1h)** — `index.html:47-48` pointe vers un PNG inexistant.
8. **Lien grille tarifaire depuis couvertines.html (≈1h)** — le contenu prix existe déjà en blog, il suffit de le linker.

Total ≈ 5h pour ces 8 corrections à fort impact / friction quasi nulle.

## 6. Ce qui marche déjà (à conserver)

- **Le formulaire de contact fonctionne** (FormSubmit.co, `contact.html:405`). Le diagnostic antérieur « formulaire mort » était FAUX — confirmé par SEO et les personas. Le téléphone et l'email marchent.
- **Fondations SEO saines** : sitemap.xml, robots.txt, canonical ×17, schema.org Product/LocalBusiness/Article/BreadcrumbList présents, Plausible RGPD-compliant installé.
- **Approche CSS fluide moderne** : 24 `clamp()` bien utilisés, `prefers-reduced-motion` présent dans styles.css/futuriste.css/preloader.css.
- **Configurateurs fonctionnels** sur le calcul (prix, développé, clamp des bornes) — la logique métier est là, c'est la pédagogie et le mobile qui manquent.
- **Identité visuelle premium** sur desktop : le hero, le marquee certifications, le diptyque sont léchés. La base design est bonne, il manque le système qui la rend cohérente.
- **Blog SEO-riche déjà écrit** (5 articles avec grille tarifaire complète) — sous-exploité par manque de maillage, pas inexistant.

## 7. Le mot brutal de fin

Le vrai blocage n'est pas le code — il est **commercial et organisationnel**. Tu as une boutique e-commerce dont la caisse est débranchée (Stripe), les rayons vides (photos/réalisations), et les vendeurs muets (Brevo, avis, fiches techniques). Aucun refactor CSS ne corrigera ça : il faut **décider** si metal-pliage.fr est une vraie boutique (alors déploie un backend de paiement cette semaine) ou un catalogue-vitrine qui pousse vers le téléphone (alors assume-le, retire le panier mort et muscle le tél/devis). Tant que cette décision n'est pas prise, tu finances du trafic vers un cul-de-sac. Le contenu (photos chantiers, avis clients, fiches atelier) ne dépend pas de Claude : **c'est toi qui le détiens, et c'est lui qui débloque 60% de la valeur de ce site.**
